# x-follow — 日报条目跟进到落地

把 x-digest 日报「可行动项」/ backlog 里的条目推进到明确结论：
可落地的改进方案（直至 PR）、认知沉淀入库、或判定为伪信号销项。一次跟进只处理一个条目。

## 输入

- 参数：backlog 编号（如「跟进 3」）、permalink，或不带参数（默认取 backlog.md 最早的 open 项）。
- backlog 位置：x-digest 技能目录下的 `backlog.md`（x-digest 日报登记，本技能销项；
  无则按 x-digest SKILL.md 中的模板创建）。

## 流程

1. **确定目标与关联仓库**：读 backlog 条目确定关联项目；先读对应仓库的 AGENTS.md /
   贡献约定，确认边界与分支规则。
2. **深读源帖**（不可跳过，禁止基于日报摘要直接改代码）：
   - 打开 permalink，读正文 + 高赞回复 + 作者本人补充；
   - 正文关键外链（repo/docs/横评全文）再跟进一层；
   - 产出借鉴点清单，逐条标注【原帖实证】或【我的演绎】，不许混。
3. **对照源码验证**：在关联仓库只读相关模块，回答三个问题——
   借鉴点我们是否已有？差距具体在哪个文件/模块？值不值得做（收益 vs 改动量）？
4. **产出判断**（三选一，先向用户报告再动手）：
   - (a) 有可落地改进 → 进入 plan 模式出方案；用户批准后实现 + 测试；
     提交/推送/提 PR 须用户明确授权，遵守仓库分支与工作树收尾规则。
   - (b) 认知输入 → 按「沉淀映射」落盘到对应仓库，销项 done，备注写沉淀文件路径。
   - (c) 伪信号/无关 → 销项为 dropped + 一行原因。
5. **销项**：更新 backlog.md 状态；(a) 类等 PR 合并后再销项。

## 沉淀映射（结论落盘，不死于对话）

首次跟进前与用户确认「沉淀映射表」，记在 backlog.md 头部。常见映射：

- **项目相关洞察** → 对应项目仓库的 docs/（轻量洞察追加 `docs/signal-insights.md`
  卡片；撑得起完整分析的写 `<slug>-analysis.md`）
- **跨项目通用经验** → 用户的笔记/经验库（独立的 notes/lessons 类仓库）
- **副业流程 / 复盘** → 副业仓库的 playbooks/ 或 research/ 目录

卡片格式：日期 / 来源链接 / 【实证】【演绎】分开标注 / 关联模块 / 状态
（待验证 → 已验证 → 已采纳指向 PR，形成闭环追溯）。

落盘规则：先写文件**不自动提交**；仓库工作树有在途改动时只新增文件、绝不动已有修改；
提交随相关 PR 一并走，或经用户授权后单独提交。

## 红线

- 演绎与实证分开标注，不把推测算实证；未运行/未验证的步骤不得写成已通过。
- 不跨仓库批量改动；不未经批准就提交或推送。
